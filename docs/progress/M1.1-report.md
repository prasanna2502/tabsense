# M1.1 Report — Side-panel UX reset

Date: 2026-10-08 · Milestone: M1.1 · Status: build complete and verified; final sign-off is the user's in-Chrome visual review

## 1. Shipped
- **Action-first panel.** The M1 layout (stat row, always-expanded sections, every open
  tab, diagnostic footer) is replaced by: a plain-language **Needs attention** card on
  top — "{N} duplicate tabs can be closed / {M} documents are open more than once" with
  **Close all extra copies** and **Review first** actions, or a calm "Everything is
  tidy" state with no fake CTA — then the duplicate cards, a reserved **Suggested
  groups** slot for M2 (hidden while empty), and collapsed secondary sections:
  Similar documents, Recently closed, All tabs (searchable), Settings & details.
- **Duplicate cards, collapsed by default.** Each exact set is a compact card —
  favicon, title, host, "4 copies · 3 extra" — with members (title + host/path) and
  the per-set "Keep newest, close N others" action inside, revealed on expand.
  Similar-document (fuzzy) sets stay display-only with a plain explanation; activity
  entries show time, title, and host with Reopen; tab rows show favicon, title, and
  host — full URLs no longer appear in any default row.
- **Global close-all.** A new worker message closes every extra exact copy at once.
  The worker plans from its live index at click time (shared pure helpers:
  `planBulkClose` / `countExtraCopies`), keeps each set's newest tab, re-validates
  every tab (tracked, not excluded, still under the planned key) before closing, and
  logs one `bulk-close` activity entry per closed tab. No browser confirm modal.
- **Toolbar badge + tooltip.** Chrome cannot open the side panel on a background
  detection event, so the badge is the ambient prompt: it shows the extra-copy count
  (`99+` above 99) with a title of "TabSense — N duplicate tabs can be closed. Click
  to review," clears when the count reaches zero, and is derived from the same live
  index and set builder as the panel, so badge and panel always agree. Action APIs
  are called only when the computed badge state changes.
- **Settings & details** now holds the auto-close toggle, a plain-language core
  status (Ready / Still loading / Couldn't start), and focus-swap timings only when
  data exists. A failed core shows a clear warning above the panel content;
  a still-loading core shows a subtle "Getting ready…". The raw normalization
  sample and engine names are gone from the UI.
- `TabInfo` now carries `favIconUrl`; rows and cards show the favicon or a neutral
  letter tile when it is missing or fails to load. No new permissions.

## 3. Decisions
- **One derivation everywhere.** Panel headline, global close-all, and badge all
  compute from `findExactDuplicateSets` + `countExtraCopies` over the same
  key-bearing tab shape, so the three numbers cannot drift apart.
- **Native `<details>` disclosures** for cards and sections — keyboard/focus
  behavior comes from the platform; open state and the All-tabs search query are
  kept in panel UI state so snapshot re-renders don't collapse what the user
  opened or eat their typing.
- **No confirm modal for close-all.** The button label states exactly what it
  does, it only ever closes exact-tier extras (never fuzzy matches, never the
  newest copy), and every close is recoverable from Recently closed.
- **Similar documents and Recently closed hide entirely when empty**, rather
  than showing zero-count sections — the default view stays about what needs
  attention.
